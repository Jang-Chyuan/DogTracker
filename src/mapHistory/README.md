# 歷史地圖

歷史地圖右側「匯出」提供 PNG／GPX／CSV，選擇儲存（Android 系統建立文件）或分享（系統分享選單，不自動傳送）。PNG 是目前可見地圖與軌跡，保留 Google 標示並加上時間區間。GPX／CSV 重新分批讀取畫面當下區間的完整 SQLite 資料，不受 4000 點绘圖上限限制，僅包含啟用來源及目前帳號的雲端資料。CSV 包含定位與寫入時間、精度等原始欄位；GPX 不含無效座標，保留斷線分段，時間為 UTC。匯出時帳號或設定變更會取消。圖片與文件暫存於限縮的 FileProvider cache 目錄，匯出時清理超過七天的暫存檔；不要求外部儲存權限。

時間模式可選「最近幾小時」或「指定日期與開始時間」。指定模式提供月曆選日期、24 小時制 HH:mm 開始時間、持續時數（可小數，最多 240），並預覽完整起訖區間。使用手機本地時區，包含起點、不包含終點，支援跨日；固定區間在定時刷新時不移動。原有設定自動沿用最近幾小時模式。

設定 → 地圖定位來源與歷史 → 開啟「顯示歷史地圖」→ 選手機／Client、BLE／Supabase、Master／Slave、最近時數 → 套用地圖設定。

手機與 Client 可獨立開關。預設保留既有即時／Demo 地圖，歷史模式不修改記錄開關。設定保存在原資料庫 `map_history_settings`，共用 tracking session 的 connection 與關閉等待機制。

歷史地圖只讀本機 SQLite，不會向 Supabase 補抓。所選範圍開始時間早於本機最舊的一筆時，地圖上方會標出本機最早只到什麼時候，並指向「設定 → 雲端資料」下載該日期（BLE 來源則說明是每隻 Slave 10,000 筆的保留規則）。選定的 Master／Slave 在本機完全沒有紀錄時也會明說，避免把「沒下載」看成「沒資料」。匯出讀的是同一份本機資料，因此同樣受限。

時間範圍以本機接收／寫入時間為準，支援 1／3／6／12／24 小時快捷或自訂大於 0、最多 240 小時。地圖前景每 10 秒移動查詢時間窗；SQLite 分批每 1000 筆讀取，時間＋id 游標避免相同時間漏筆。手機最多既有 80000 筆；Client 受 BLE 每 Slave 10000 筆或雲端全域 15000 筆保留規則限制。

雲端僅顯示目前登入帳號下載的 owner_user_id，不登入不讀雲端。帳號／選項變更立即隱藏舊查詢結果；雲端查詢前先完成原有 migration。BLE 與雲端不合併。

手機藍色、Client 紅色，標記顯示該期間最後有效位置與時間、速度。無效定位或超過 2 分鐘中斷會分段。3 公尺幾何簡化後每來源最多 4000 繪圖點，超量僅顯示較新部分並提示，不刪除資料。切換條件時適應軌跡範圍，定時刷新不干擾手動視角。
