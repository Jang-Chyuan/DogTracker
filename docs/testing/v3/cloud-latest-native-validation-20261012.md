# 2026-10-12 雲端最新位置修正與原生驗證

回前景或冷啟動時，最新位置使用獨立 SQLite 檔案、原生工作執行緒、鎖與下載排程，不必等舊歷史資料庫維護完成。真正由地圖讀取並接受完整最新快照後，結束前景更新狀態；完整歷史繼續背景補齊，未完整的狗歷史保留載入限制。手機自己的歷史讀取不再等待狗的雲端下載門檻。

## 完整性與啟動條件

- 冷啟動保留原有本機／設定／地圖啟動條件，再加入最新位置接受條件；失敗依既有設計進地圖顯示錯誤提示，沒有新增 splash 按鈕。
- 保留所有可存取的狗，有限四 key 預取、兩個狗下載 worker；手機與接收時間分流比較，最新封包與有效定位分別取得，整批原子提交。
- 跨最新／歷史兩檔刪除以持久 deletion_pending 和 epoch 保護。刪除未完成時拒絕讀取或重新發布狗資料，錯誤可於設定重試；已開始的舊原生交易仍會完成，不宣稱取消可搶占它。
- 帳號、範圍、取消及過時結果均有檢查；未接受最新位置時不開放狗歷史，手機自己的本機歷史有獨立門檻。
