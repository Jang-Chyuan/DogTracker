# DogTracker Project Guide

DogTracker is a React Native Android app that connects to compatible Heltec V4 `DogGPS-MasterN` devices over BLE. It receives the OLED dataset generated by the connected Master and displays GPS, distance, activity, signal and battery values.

## Current Features

- Scan and connect to compatible `DogGPS-MasterN` devices, including Master 3 and Master 5, using device-specific QR configuration.
- Scan QR codes offline with an in-app CameraX preview and the bundled ML Kit barcode model; only QR format is enabled and results are validated by `parseMasterQr()`.
- Subscribe to BLE GATT notifications.
- Keep the BLE session in an Android connected-device foreground service and restore the GATT subscription after system process recreation.
- Display Slave and Master GPS, distance, speed, satellites, HDOP, activity, RSSI, SNR and battery status.
- Support BLE permissions required by Android 8.1 and Android 12+.
- Build a standalone Release APK that does not require USB or Metro.

## Module Ownership

```text
App.js                    # App entry point and BLE realtime UI
src/
├─ ble/                    # Task A: BLE scan, connection and parsing
│  ├─ BleService.js
│  ├─ BleScanner.js
│  └─ BleParser.js
├─ gps/                    # Task B: phone GPS interface
│  └─ LocationService.js
├─ database/               # Task C: SQLite interface
│  └─ DogDatabase.js
├─ screens/                # Task D: screen components
│  ├─ MapScreen.js
│  └─ HistoryScreen.js
├─ map/                    # Task E: map interface
│  └─ DogMap.js
└─ models/                 # shared data format
   └─ DogStatus.js
```

Each Task should modify its own directory. Cross-task data must pass through `src/models/DogStatus.js` or an explicit module interface. Avoid putting feature logic back into `App.js`.

| Task | Owner | Responsibility |
| --- | --- | --- |
| A: BLE | `src/ble/` | Permissions, scan, GATT connection, Notify, Base64 and JSON parsing |
| B: GPS | `src/gps/` | Phone location permission and location provider |
| C: SQLite | `src/database/` | Schema, status history persistence and queries |
| D: UI | `src/screens/` | Screens and navigation |
| E: Map | `src/map/` | Map component and coordinate presentation |

## Shared DogStatus Model

BLE data is normalized by `toDogStatus()` in `src/models/DogStatus.js`. UI, GPS and database modules should use the normalized camelCase fields, not raw BLE keys.

```text
masterId, slaveId, slaveLat, slaveLon, masterLat, masterLon
distanceMeters, speedKmh, satellites, hdop
activity, activityValid, rssi, snr
batteryMillivolts, batteryPercentage, batteryValid
masterBatteryMillivolts, masterBatteryPercentage, masterBatteryValid
gpsTime, activityTime, type, sequence, length
```

## BLE Protocol

| Item | Value |
| --- | --- |
| Device name | `DogGPS-MasterN` (provided by the device QR configuration) |
| Service UUID | `7f510001-6d9e-4e2f-a671-8f3f2d49a001` |
| Data Characteristic UUID | `7f510002-6d9e-4e2f-a671-8f3f2d49a001` |
| Wi-Fi Config Characteristic UUID | `7f510003-6d9e-4e2f-a671-8f3f2d49a001` |
| Direction | Master Notify to phone |

The Master sends a compact OLED dataset. Current compact keys include:

```text
slat/slon   Slave coordinates
mlat/mlon   Master coordinates
dst         distance in meters
spd         speed in km/h
sat/hd      satellites / HDOP
act/av      activity / activity-valid flag
bmv/bp/bv   Slave battery millivolts / percentage / valid flag
mbmv/mbp/mbv Master battery millivolts / percentage / valid flag
rssi/snr    LoRa signal quality
gt/at       GPS and activity timestamps
```

The BLE Characteristic must have one publisher. The current Master publishes the complete OLED dataset from its OLED task to prevent competing long and short JSON notifications.

On Android, the connected device ID, display name and GATT UUIDs are persisted when a session starts. While the React Native process is alive it owns the active connection. If Android recreates the sticky foreground service after killing the process, the Kotlin service restores the GATT connection, subscribes to notifications and retries with a 2–30 second exponential backoff. Explicitly stopping background reception clears the restore flag.

Wi-Fi settings use a write-with-response characteristic. The phone sends
`{"action":"upsert","ssid":"network-name","password":"network-password"}` as Base64-encoded UTF-8 JSON. Compatible Master firmware exposes the Wi-Fi Config Characteristic as writable.

## Development

Requirements:

- Windows
- Node.js `>= 22.11.0`
- Android SDK, Platform Tools and JDK
- React Native `0.87.0`

Install dependencies:

```powershell
npm install
```

Start Metro and run a USB-connected Debug build:

```powershell
npm start
adb devices
adb reverse tcp:8081 tcp:8081
npm run android
```

Debug builds require Metro. Do not use `npm run android` when the goal is a USB-independent installation because it installs a Debug APK.

## Test and Release

```powershell
npm run lint
npm test -- --runInBand
```

Build a standalone APK:

```powershell
cd android
.\gradlew assembleRelease
cd ..
```

Output:

```text
android\app\build\outputs\apk\release\app-release.apk
```

Install it on a connected device:

```powershell
adb install -r android\app\build\outputs\apk\release\app-release.apk
```

The Release APK includes the JavaScript bundle and can start without USB or Metro. BLE still requires Bluetooth and the Android location/Bluetooth permissions requested by the app.

## Git Collaboration

Use one feature branch per Task:

```powershell
git switch -c feature/task-name
git status
git add <your-files>
git commit -m "feat: describe the change"
git push -u origin feature/task-name
```

Open a Pull Request into `main`. Before merging, run lint and tests; BLE or Android permission changes should also pass a Release build.

## Reserved Modules

The following modules are intentionally interfaces/placeholders for later Tasks:

- `src/gps/LocationService.js`: phone GPS provider
- `src/database/DogDatabase.js`: SQLite driver and persistence
- `src/map/DogMap.js`: map implementation
- `src/screens/MapScreen.js`: map screen
- `src/screens/HistoryScreen.js`: history screen
